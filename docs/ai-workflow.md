# AI編集と区分ごとの分類

## AI編集

- 既存のChatGPT接続・契約枠を使います。OpenAI API従量課金への切り替えはありません。
- 通常は「速く答える」（low reasoning）。必要なら「じっくり考える」（medium）を選択できます。モデル自体は選択されたものを保持します。
- 作業中の「中断」で停止できます。入力欄から追加指示を送ると、進行中の処理を中断して、元の依頼と追加指示を引き継いで再実行します。中断した依頼は履歴に残ります。
- 失敗した依頼には理由と「再送信」を表示します。端末を閉じて履歴だけが残った依頼も再送信できます。
- 変更案は本文に表示するだけで、採用まで保存されません。「この回答の変更をすべて採用」または「このリーフの変更をすべて採用」でまとめて採用できます。
- 一括採用はチェックポイント保存後、全対象の最新本文を検証し、重複・古い提案が1つでもあれば全体を止めます。別リーフと同一段落内の独立した提案に対応し、関係ないYjsブロックのIDを維持します。

### 待機と中断の実装

ローカル接続はNDJSONで進捗と完了結果を分けます。接続切断・中断で上流のResponsesストリームも中断します。旧クライアントのJSON応答も維持しています。

中継は既存の所有者限定 `ai_requests` テーブルを使用します。SQL変更は不要です。中断は `queued/running` から `failed` への条件付き更新です。Macは実行中に状態を監視し、キャンセル済みのリクエストを完了結果で上書きしません。進捗と生存確認には `running` 中の `result.progress` と `updated_at` を使います。中断後は次の待機リクエストをすぐに確認します。

以前の120秒固定終了を、上流通信の90秒無通信検出と10分の全体上限に変更しました。認証更新・モデル一覧・Supabaseへの問い合わせも待機上限で保護します。画像のbase64バイト列は送信せず、画像を含む変更案は受け付けません。本文合計18万文字、直近8件・1.6万文字以内の会話を送信します。大きすぎる参照範囲は、黙って切り捨てず範囲を絞るよう案内します。

認証情報はMacの保護された既存ランタイムだけに保存します。認証期限切れは再ログインを案内し、一時障害では認証情報を保持します。同期へのログインとMacの接続が有効な場合、中継が切れていれば自動で再接続します。

## 区分ごとの分類

| 区分 | 分類 | 選び方 |
| --- | --- | --- |
| 本 | ジャンル | 金融・回顧録・政治・SF等を複数選択。追加可能 |
| 論文 | 大カテゴリ → 中カテゴリ → 小カテゴリ | 各段階1つ。上位カテゴリごとに選択肢を分離。追加可能 |
| ノート | インプット・アウトプット | Podcast・記事・動画・自分のアウトプット等を複数選択。追加可能 |
| 日記 | なし | 分類の入力・バッジ・絞り込みを表示しない |

従来の `tags` と `labels` は削除も自動変換もしません。日記以外では「以前のタグ」から確認できます。分類は別の追加フィールド（`bookGenres`, `paperMajor`, `paperMiddle`, `paperMinor`, `noteTypes`）、選択肢は区分・親パスで分離した `taxonomy-labels` に保存します。区分を切り替えても以前の区分の値は保持します。論文の上位を明示的に変更したときだけ従属する選択を解除します。

検索と絞り込みは分類に対応し、同名の分類が別の区分や論文の別の親カテゴリに混在しません。バックアップv1の形式、保存先、既存ID、同期の所有者関連付けは変更していません。復元コピーにも分類を引き継ぎます。

## 検証

`npm test`, `npm run build`, `PAGES_BUILD=1 npm run build`, `node scripts/check-secrets.mjs`。

独立した開発オリジンの合成データで `test/editor.html` を開き、一括採用、プレビューの非破壊性、書式・画像・音声の挿入位置、旧バックアップの互換性と復元を確認します。本人の記録をテストに使わないでください。
