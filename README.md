# Marginalia — 思考の余白

研究・勉強ノート、論文や本の読書記録、日記をつなぐ個人用Webアプリです。

公開先: https://harukisoma.github.io/marginalia/

## 使い方

- 記録の総称は「リーフ」。本・論文・ノート・日記の4区分があり、「ノート」は動画からの学びや自分の考えをまとめる場所です。ライブラリでは4区分を俯瞰できます。
- 一覧は「ページビュー」と「ギャラリー」を切り替えられます。表示形式と開いたタブは端末ごとに保存します。
- 左にリーフ一覧、中央にブロック文書、右にAIチャット。iPhoneでは画面を切り替えて使います。
- ブラウザ標準の「戻る」「進む」、または上部の矢印で、リーフ・各区分・検索結果の閲覧履歴を移動できます。リーフのURLを再読み込みしても同じリーフを表示します。未反映のMarkdown原文がある状態で履歴を移動した場合は、下書きを端末に保存し、元のリーフの「Markdown原文」で復元します。
- タブの「×」は表示だけを閉じます。リーフは残り、一覧から再び開けます。最後のタブを閉じるとライブラリへ戻ります。
- 本文右上・一覧・左バーの「…」→「ゴミ箱へ移す」で削除します。「元に戻す」またはゴミ箱から本文ごと復元できます。Markdown原文に未反映の変更がある場合は、反映またはキャンセル後に閉じる・削除できます。
- `/` または「＋」でブロックを追加。見出し1〜3、本文、リスト、チェックリスト、引用、表、画像、数式、コード、脚注、ページ埋め込みを使えます。
- ツールバーの「文字色とハイライト」から、セージ・ブルー・オーカーなど6色の文字色と、6色の淡いハイライトを選べます。ダークモードでも読みやすい配色に切り替わります。
- 太字、斜体、取り消し線、下線、文字色、ハイライト、上付き・下付き文字に対応します。
- Markdownを貼り付けると文書へ変換します。「Markdown原文」で直接編集・反映でき、`.md` ファイルの読み込み・書き出しもできます。
- 数式は `$...$`、`$$...$$`、`\(...\)`、`\[...\]` で入力できます。数式をクリックするとTeXを編集できます。行列、複数行の式、AMS系の数式をMathJaxで描画します。
- コードは指定言語で色分けします。言語未指定の場合は自動判定します。
- `![[ページID]]`、または「ページ埋め込み」で他ページの本文を表示します。埋め込みから元のページへ移動できます。
- ページや文書はブラウザ内に自動保存します。初回オンライン訪問後はアプリ自体もキャッシュされ、オフラインで閲覧・編集できます。
- ゴミ箱から復元でき、設定画面から全体のバックアップを保存・読み込めます。

標準MarkdownとGFMの表・チェックリスト・取り消し線に加え、脚注、ハイライト、上下付き、数式、ページ埋め込みを扱います。複雑なHTMLは原文を保持する拡張ブロックになります。未知のMarkdown方言をすべて自動解釈するわけではありません。ブラウザで表示する数式用TeXを対象としており、LaTeX文書全体やTikZをコンパイルする機能ではありません。

## 音声入力

上部の雲ボタンからクラウド同期へログインし、本文の「音声入力」→「音声入力を開始」を押します。話している途中から文章を表示します。「停止して確認」後に修正・コピーでき、「本文に挿入」を押すとカーソル位置へ追加します。選択していた文章も保持し、挿入前に復元用コピーを保存します。

OpenAIの **GPT-Live-Transcribe**（`gpt-live-transcribe`）をRealtime API / WebRTCで使います。日本語と英語を候補言語に指定するので、切り替え操作は不要です。認識の遅延設定は精度を優先する `high` にしています。音声はOpenAIへ送信し、API料金は音声1分あたり $0.017（2026年11月19日の公式料金）です。APIクレジットが必要です。

録音は1回5分までで、画面を離れると停止します。接続が切れた場合も受信済みの文章を確認・コピーできます。本文は挿入するまで変えません。既存のリーフや日記を音声の認識用コンテキストとして送信しません。MacのAI補助サーバーは不要です。

### 音声APIのサーバー設定

1. OpenAI PlatformでRealtime APIのRequest権限を持つ専用キーを作り、APIの支払い設定を完了します。
2. SupabaseのEdge Function Secretsへ `OPENAI_API_KEY` と `VOICE_ALLOWED_USER_IDS`（本人のSupabase AuthのユーザーID）を設定します。許可IDが空なら利用を拒否します。APIキーをブラウザ、GitHub、リーフに保存しません。
3. `supabase/functions/voice-session/index.ts` を `voice-session` としてデプロイします。`supabase/config.toml` のとおり、legacy secretだけを認めるゲートウェイ検証は使わず、関数内でSupabase Authへ問い合わせてJWTを検証し、利用者IDを照合します。
4. CORSは既定で `https://harukisoma.github.io` のみを許可します。開発オリジンを追加する場合は、サーバーの `VOICE_ALLOWED_ORIGINS` で完全なオリジンを列挙します。

ブラウザには有効期間30秒の一時認証だけを返し、長期APIキーを返しません。関数は音声や文字起こしを受け取りません。認証・モデル指定・エラー時の秘密情報の非開示・最終文章の確定と順序・マイクの解放を自動テストします。

旧Whisper実装とTransformers.js依存は撤去しました。更新時は旧モデルの再取得可能なダウンロードキャッシュだけを整理します。リーフの保存領域とバックアップには触れません。

公式仕様: [Realtime transcription](https://developers.openai.com/api/docs/guides/realtime-transcription)、[GPT-Live-Transcribe](https://developers.openai.com/api/docs/models/gpt-live-transcribe)

## 更新とデータ保護

リーフの保存先はリリースから独立した固定名のIndexedDBと本人のクラウド領域です。アプリ更新で本文を初期化しません。変更案のプレビューも保存文書へ入りません。

- 更新の直前、更新後の初回起動時、初回同期前、AI変更の採用やゴミ箱への移動の前などに、別のIndexedDBへ長期保護のコピーを保存します。編集中は約5分おきに定期保存します。定期保存の直近30件とは別に長期保護のコピーを保持します。
- 「設定と接続」→「自動バックアップから復元」で、このブラウザのバックアップを確認できます。数式・コード・装飾・ゴミ箱のリーフも含みます。日記一覧が空の場合は、一覧からゴミ箱とバックアップを確認できます。
- 過去の本文を復元すると、タイトルに「（復元）」の付いた別リーフを作ります。現在の本文は残ります。保存した `.json` の読み込みも、復元画面で内容を確認してからコピーする方式です。
- 保存形式の固定テスト、旧v1形式の固定フィクスチャ、プレビューの非破壊性、変更対象以外のブロック保持を確認します。`AGENTS.md`にも、保存先変更・初期化・本番データでのテストを避ける開発上の規則を置いています。

同期によって既存のリーフが完全に消える場合は同期を停止します。

自動バックアップはこのブラウザ内の復元用コピーです。サイトデータ削除や端末故障に備えるため、クラウド同期と全リーフのファイル保存も使えます。

## クラウド同期

このリポジトリには、本人のSupabaseプロジェクトのURLと **publishable key** を初期設定しています。このキーは公開可能なもので、リーフには本人のログインが必要です。秘密鍵・`service_role` キーはアプリやリポジトリへ入れません。

1. 公開アプリの上部にある雲のボタンを押し、メールアドレスを入力して認証メールを送ります。
2. iPhoneのホーム画面版では、メールに届いた認証コードをアプリ内の「メールの認証コード」に入力します。リンクを使う場合は、メール内のリンクを長押しでコピーし、「メールのリンクをここで使う」にペーストしてログインできます。
3. MacとiPhoneで同じメールアドレスを使い、「同期済み」と表示されることを確認します。各端末の既存リーフはクラウドの内容と統合されます。

コードをメールに表示するには、Supabaseの Authentication → Email Templates の「Magic Link」と、新規登録用の「Confirm signup」の本文に `{{ .Token }}` を含めます。既存のリンクも使う場合は `{{ .ConfirmationURL }}` を維持します。

同期画面にはログイン中のメールアドレスと最終同期時刻が表示されます。編集後は自動で同期し、アプリへ戻ったとき、通信復帰時、利用中は15秒ごとにも確認します。「今すぐ同期」で手動の再試行ができます。ログアウトは操作した端末に適用し、端末内のリーフは保持します。

Yjsが文書・ページごとの編集を管理し、IndexedDBへ保存します。再接続時はクラウドの状態を読み込んで統合し、版番号を確認して保存します。同時保存で版番号が変わった場合は読み直して再試行します。クラウド同期に失敗しても端末内の編集を残し、状態を表示します。別のログインアカウントへ既存リーフが送られないよう、同期アカウントを端末に関連付けます。

ブラウザのサイトデータ削除やプライベートブラウズは端末保存を消す場合があります。未同期の重要なリーフは全体バックアップも保存してください。

別のSupabaseプロジェクトを使う場合:

1. SQL Editorで `supabase/schema.sql` と `supabase/relay.sql` を一度ずつ実行します。
2. Authentication → URL Configurationに公開アプリURLを設定します。MacでAIを使う場合は `http://127.0.0.1:4318/` も戻り先へ追加します。
3. アプリの「接続先の詳細」でProject URLとpublishable keyを指定します。

Realtimeは任意です。未設定でも定期取得と接続復帰で同期します。

## ChatGPTの契約を使う

OpenAI公式の **Sign in with ChatGPT** を使用します。APIキーの入力や従量課金APIへの自動切り替えはありません。利用できるモデルはログインしたアカウントから取得します。ChatGPTの契約・アプリごとの利用上限が適用されます。無制限を保証するものではありません。

OpenAIの公開クライアント認証は `127.0.0.1` のコールバックと保護されたローカル保存を使います。GitHub PagesのJavaScriptだけで認証情報を扱わず、Macの補助サーバーが認証とAIリクエストを担当します。

### Macで最初に接続する

Node.js 22以上が必要です。

```sh
npm ci
npm run build
npm run companion
```

1. `http://127.0.0.1:4318/` を開きます。
2. 設定画面の **Continue with ChatGPT** を押し、本人のChatGPTアカウントで認証します。
3. アプリに戻って「接続を確認」を押します。
4. GitHub Pages版で直接Macに接続する場合は、補助サーバー起動時の接続コードを設定します。ブラウザがローカルネットワーク接続の許可を求めることがあります。

認証情報は `.runtime/` に本人だけが読める権限で保存します。GitHub、ノート、ブラウザの保存領域へOpenAIのトークンを送信しません。再認証、トークン更新、切断を実装しています。

### iPhoneからAIを使う

1. 公開アプリでクラウド同期へログインし、MacのAI接続コードを設定します。
2. 「このMacをiPhone用のAI接続端末にする」を押します。別画面で初回設定の完了を確認します。
3. 公開アプリに戻って「接続を確認」を押します。
4. iPhoneの公開アプリで同じ同期アカウントにログインします。

iPhoneの依頼は本人専用のクラウド領域に入り、Macが実行して応答を返します。**AIを使う間はMacが起動していて、補助サーバーが動いている必要があります。** Macが応答できない場合も、ノートの閲覧・編集・同期は使えます。依頼と応答は本人のクラウド領域に保存されます。OpenAIの認証情報はMacに残ります。

公開Webサービスとして他人に提供する場合は、Sign in with ChatGPTの提供条件を改めて確認してください。この実装は本人が管理するローカルAI実行環境を使う個人用ツールです。

### AIでできること

文章整理、推敲、TeX・コードの表記修正、要約、指定ページや日記を除いた全リーフを参照した回答を依頼できます。チャットには参照リーフと「ページで確認」を表示し、変更案は対象リーフの該当ブロック内に重ねて表示します。変更前と変更後を文書の装飾・MathJaxの数式・色付きコードで比較し、変更案ごとに採用・却下できます。処理中は動く表示と経過時間が出ます（動きを減らす設定にも対応します）。承認前は本文を書き換えません。対象の文章が更新されたり複数箇所に存在したりする場合は、上書きせず再提案を促します。コード実行・外部Web検索など、未実装の操作を実行したとは表示しません。

公式仕様:

- https://developers.openai.com/siwc/token-sharing-open-source/sign-in
- https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference
- https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions

## 開発と公開

```sh
npm run dev
npm test
npm run build
```

GitHub PagesのSourceをGitHub Actionsに設定します。`main` に変更を保存すると、テスト・ビルドを実行して公開します。リーフ本文、ブラウザの保存データ、`.runtime/` は公開対象に含みません。

テストはOAuthのPKCE・state・client ID検証、AI変更対象の確認、通信中断と利用上限の処理、複雑な数式の変換、オフラインでの同時文書編集の統合を確認します。ブラウザの実エディタでも、数式・表・脚注・装飾・ページ埋め込みの再変換、部分承認で他のブロックが残ること、別ページへの変更、古い変更案の拒否を確認します。開発時は `/test/editor.html` で実行できます。ログインを伴う実接続は本人の認証後に確認します。
